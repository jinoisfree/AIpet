# 앱 내 업데이트

Mac 1.0.12와 Windows 1.0.12-preview.1부터 지원한다. 이 기능이 없는 구버전은 최초 한 번
새 배포본을 수동으로 설치해야 한다. 이후에는 앱이 새 버전을 안내하고 사용자가 동의하면 설치한다.

## 사용 동작

앱 실행 약 20초 후 확인을 시작한다. 마지막 조회가 6시간 이내이면 건너뛰며, 실행 중 15분마다
조회 시점이 되었는지 확인한다. 실패해도 자동 확인은 대화상자를 띄우지 않는다. 메뉴의
**업데이트 확인…**은 간격과 자동 확인 설정에 관계없이 조회하고 결과나 연결 실패를 알려준다.
**업데이트 자동 확인**은 기본 켜짐이며 사용자가 끄면 다음 자동 요청부터 멈춘다.

새 버전 안내에서 동의하기 전에는 메타데이터만 받는다. 거절한 버전은 24시간 동안 자동 안내하지 않는다.
그보다 새로운 버전은 안내할 수 있으며 수동 확인은 보류 기간에도 안내한다. 다운로드 중 취소할 수 있다.
동일하거나 낮은 버전은 설치하지 않고 중복 확인·설치는 한 번에 하나만 진행한다.

Mac은 현재 실행 중인 앱의 위치를 유지한다. 쓰기 권한이 없다면 응용 프로그램 폴더 등 쓰기 가능한
위치에 설치하라는 안내를 표시한다. 새 앱을 같은 볼륨의 임시 폴더에서 검증하고, 기존 앱이 종료된 뒤
별도 도우미가 기존 앱을 백업하고 새 앱을 옮겨 재실행한다. 성공하면 백업과 다운로드를 제거한다.
교체·검증·실행 명령이 실패하면 기존 앱을 복원한다. 복원마저 실패하면 백업을 삭제하지 않는다.
이름·크기·위치와 업데이트 설정은 앱 번들 밖의 UserDefaults에 그대로 남는다.

Windows는 기존 Inno Setup 설치 프로그램을 진행 표시와 함께 실행한다. 설치가 시작되면 AIpet이
설정을 저장하고 종료하며, 설치가 끝나면 새 AIpet을 실행한다. 설치 위치·AppId·제거 항목은 유지한다.
ZIP 사용자는 `%LOCALAPPDATA%\Programs\AIpet` 설치본으로 전환된다. 기존 사본 정리는 설치 프로그램의
신원 확인과 실행 위치 기록 범위에서만 수행한다. `%APPDATA%\AIpet` 설정과 `%LOCALAPPDATA%\AIpet` 기록은
지우지 않는다. Windows 다운로드 캐시에 설치 파일이 남을 수 있으며, 별도의 설치본을 추가하는 것은 아니다.

## 릴리스 조건

커밋·브랜치 푸시는 업데이트 배포가 아니다. 공개 저장소 `jinoisfree/AIpet`의 Releases 목록에서
플랫폼에 맞는 태그와 에셋을 찾고 버전 숫자를 비교한다. 목록의 첫 100개 공개 릴리스를 검사한다.
Mac과 Windows가 같은 저장소를 쓰므로 `/releases/latest`는 사용하지 않는다.

| 대상 | 태그 | 필수 파일 | 앱에 넣을 버전 |
|---|---|---|---|
| Mac arm64 | `v1.0.12` | `AIpet-1.0.12-arm64.zip` | `CFBundleShortVersionString=1.0.12` |
| Windows x64 | `windows-v1.0.12-preview.1` | `AIpet-Setup-win-x64.exe` | `Version=1.0.12-preview.1`, 숫자 버전 `1.0.12.1` |

다음 배포에서는 이 표의 숫자를 올린다. Mac은 정식 `X.Y.Z` 태그만 허용하며 GitHub prerelease는
제외한다. Windows는 `windows-vX.Y.Z`와 `windows-vX.Y.Z-preview.N`을 지원한다. 같은 버전의 정식은
미리보기보다 높으며, Windows 미리보기도 자동 안내 대상이다. 초안·미게시 릴리스와 설치 파일이 아직
준비되지 않은 릴리스는 건너뛴다. 같은 이름의 에셋이 중복되거나 GitHub의 SHA-256 digest가 없으면 건너뛴다.

배포 순서:

1. Mac Info.plist, Windows csproj·installer/AIpet.iss·워크플로 ZIP 이름의 버전을 맞추고 검사한다.
2. Mac은 `bash scripts/build.sh`, `bash scripts/package.sh`로 ZIP을 만든다. Windows는 CI의 설치·업그레이드
   검사까지 통과한 `AIpet-win-x64` 산출물을 사용한다.
3. 검증한 커밋에 위 형식의 태그로 Release를 만들고 파일을 업로드한다. 모두 올라간 뒤 초안을 공개한다.
4. Releases API에서 태그·파일명·`state=uploaded`·size·`digest=sha256:…`를 확인한다.
5. 이전 앱에서 수동 업데이트 확인 → 동의 → 교체·재실행 → 버전·이름·크기·위치 유지를 확인한다.
6. README의 현재 배포 링크와 버전 안내를 실제 배포본에 맞춘다.

## 검증과 신뢰 범위

조회에는 GitHub 로그인 토큰이나 AI 계정 정보를 보내지 않는다. GitHub 공개 HTTPS API와 해당 저장소의
정확한 다운로드 주소만 사용한다. 다운로드 리디렉션은 GitHub와 GitHub 에셋 CDN의 HTTPS만 허용한다.
메타데이터는 8 MiB, 다운로드는 256 MiB로 제한하고 크기·SHA-256이 일치해야 설치 단계로 넘어간다.
Mac ZIP은 경로 이탈·심볼릭 링크·중복 항목·512 MiB 초과 압축 해제 크기 등을 거부한 후 추출하며,
앱 신원·버전·코드 서명을 다시 확인한다.

신뢰 기준은 GitHub 저장소와 HTTPS를 통해 받은 에셋 digest다. 별도의 배포자 서명 키는 사용하지 않는다.
현재 Mac은 ad-hoc 서명이고 Windows 실행 파일은 서명되지 않았으므로 Developer ID 공증이나 Authenticode
배포자 인증을 제공하는 것은 아니다. 다운로드 오류·취소·해시 불일치는 설치 전에 중단한다.
